## 2. Wilma LinkedIn caption truncation
Root cause: OpenRouter `tailor()` accepted ANY non-empty text, including `finish_reason="length"`
partials; the Wilma gate only checked leaks + a 400-char floor. Reflections were complete — the cut
happened in tailoring (day_7 "If you have", day_8 "not in something that", day_11 "Cheating dropped because no").
Fix (two layers):
- `scripts/openrouter_captions.py`: max_tokens 1024→2048; reject `finish_reason=="length"` and fail over;
  added "Here's a simple/quick/…" to `_META_OPENERS`.
- `forwilma/wilma_bot.py`: `_wilma_caption_complete()` (body must end in terminal punctuation) wired into
  BOTH gate call sites (main generate_all loop + resume path); incomplete → deterministic fallback.
Commit: 88762d5c.
Verified: gate rejects day_7/8/11, accepts day_6/9/10; synthetic controls pass;
tests/test_platform_tailoring.py 5 passed + 7 subtests.

## 3. Main-brand content gate leaks

## 6. HyperFrames reels — state-of-the-art upgrade, integrated + auto-rendered
Prior state: HTML/GSAP compositions + npm renderer existed but were workflow_dispatch-only and BROKEN.
Root causes of "Composition has zero duration" render failure:
- All 3 templates had escaped `<\/script>` closing tags (invalid HTML) → browser never closed the GSAP
  script tag and swallowed the whole document → runtime saw data-duration unset + empty window.__timelines.
  Fix: literal `</script>` (6 tags across hook-machine/bold-bright/educational-save). Commit d5ea7d5d.
- An `animation: … infinite` CSS loop also defeats duration inference → made finite (`1 forwards`).
  Commit 4611a5cc.
Commit-back failure (HTTP 408): `git add -A` after `npm install` staged node_modules/ → huge push timeout.
Fix: stage ONLY the reel; /tmp backup + fetch/reset/re-add 3-attempt push. Commit 09c1902a.
Auto-render: cron '45 2 * * *' (after 02:00 gen) resolves active_bundle post_id (input now optional/honored).
Consumption: publish.py:433-436 prefers reels/reel_<id>_hyperframes.mp4 over the PIL reel (PIL = fallback).
Verified: run 44607478379 success; reel_361_hyperframes.mp4 committed to master (blob 289f2493).
ffprobe: h264, 1080x1920, 270 frames, exactly 9.0s, 2.3 MB. Render ~30s.
Vision on extracted frames (1s/4.5s/8s): bold kinetic hook, clean typography hierarchy, high-contrast

## 7b. AI Horde kudos-guard (priority-aware fallback)
Root cause: on a congested queue the old code submitted, polled ~14 min, then RESUBMITTED on timeout
without cancelling — each submit charges upfront kudos and the abandoned job still spends when it later
completes, so a slow queue multiplied spend (a scheduled Wilma gen burned ~330 kudos this way).
Fix (bot.py, covers main + Wilma via generate_image): HORDE_MAX_WAIT_S (env, default 150s). On the first
status poll, if wait_time > threshold -> DELETE the job (cancel refunds upfront kudos while queued) -> go
straight to fallback, NO resubmit (image raises HordeQueueTooLong caught non-retryably; text returns "").
On polling timeout also cancel + fall back. queue_position is kudos-relative (= priority); wait_time is the
estimated seconds. Low priority -> quick fallback at ~0 net kudos; trusted + high kudos -> short wait ->
Horde stays default, fallbacks preserved. Commit bfbc6efd.
Verified: mock tests (image 3 scenarios, text 2) — long wait->bail+1 cancel, short-wait-stall->timeout+1
cancel, done-first-poll->success+0 cancel. Read-only live probe: installed key = iyeque#606751, 120 kudos
usable, trusted=False (worker's ~11k kudos pending until trusted); only Juggernaut XL + DreamShaper XL
online at probe time.

## 7d. Stale carousel.json forced carousel every day (reels never posted)
Symptom: main IG posted a carousel daily (not just Mon/Wed/Fri), stale slides reused, and no reels
appeared despite HyperFrames rendering daily. Root cause: a committed, stale `carousel.json` at repo
root. `prepare_assets.py:579` treated `generated_carousel_paths` (populated from that file) as an
intentional-carousel signal, forcing `instagram_format.txt = carousel` on EVERY weekday — including
reel days (Tue/Thu/Sat). publish.py only posts a reel when the marker says reel, so reels were starved.
Fix: the carousel override now depends only on an EXPLICIT signal — `INSTAGRAM_CAROUSEL_WORKFLOW=1`
(dedicated workflow) or `bundle_format == "carousel"` — not on a stale on-disk manifest. Removed the
committed `carousel.json` + `carousel_hosted_urls.json`, and both carousel workflows now `rm -f` their
manifest in the post-publish commit step (incl. retry paths) so it can't leak into later runs. Cadence
restored: Mon/Wed/Fri carousel, Tue/Thu/Sat reel, Sun static. Commit a4fd85e1.
Verified: cadence decision checks (stale manifest no longer forces; explicit override still wins),
py_compile, full suite 11 passed + 7 subtests.
